# ADR 0002. Микрофронтенд редактора схем и доска PixiJS

**Статус:** реализовано; результаты визуальных, браузерных и нагрузочных проверок фиксируются отдельно в `docs/editor`.

**Область:** приложение `apps/editor`, подключение к `apps/client`, графическая доска и минимальная DOM-оболочка.

**Исходная реализация:** ADR 0001 находится в `artifacts/adr/0001-canvas-schema-editor-and-api.md`. Архитектурные границы определены в `ARCHITECTURE.frontend.md`. Внешний вид задан пакетом `/home/neoplasmes/third_course_reimagined/artifacts/schema-editor-design`.

## 1. Решение и граница приложения

Редактор является отдельным приложением monorepo с собственными сборкой, проверками и standalone. Хост передаёт идентификатор ресурса, адрес API и callbacks. Он не передаёт дерево, хранилище, контекст React или графические объекты. Экспорты: `./Editor` и `./mount`. `mount` управляет отдельным React root и возвращает `update` и идемпотентный `unmount`.

Ресурс имеет форму `{ kind: 'schema', schemaId, revision? }` либо `{ kind: 'analysis', analysisId, revision, rootAlternativeId? }`. Не существующий на сервере projectId не вводится. Анализ неизменяем, редактирование требует отдельного черновика. Подтверждённое сохранение сообщает `{ schemaId, revision, savedAt }`; время является клиентским временем подтверждения.

Старый сервер предоставляет временную upload-сессию, WebSocket и экспорт целого дерева, но не API v2. Поэтому production-адаптер реализует контракт ADR и явно сообщает об отсутствии API. Standalone использует отдельный fixture-адаптер. Ошибка production-загрузки не включает демонстрацию. Старый пользовательский маршрут сохранён как `/edit/legacy` до реализации backend API v2.

## 2. Соответствие слоям frontend

| Путь | Ответственность |
|---|---|
| `core/entities/schema` | Типы схемы и идентичностей |
| `core/processes/document_edit` | Чистые правила переименования, переноса и проверки предков |
| `app/editor/document` | Реплика документа: базовые страницы, история, операции, подтверждение сохранений |
| `app/commands`, `app/queries`, `app/ports` | Прикладные операции и независимые от фреймворков контракты |
| `env` | HTTP transport, проверка DTO, преобразование ответов, кеш страниц, fixture repository |
| `main` | Создание transport/repository, готовых команд/запросов и React entry |
| `ui/pages/editor` | React-контроллеры, проекция документа в BoardModel и useSchemaBoard |
| `ui/widgets/editor_shell` | DOM-панели и доступное дерево |
| `board` | UI без React: Pixi, геометрия, камера, жесты, текст |
| `shared/ui/theme` | Общие для UI сгенерированные CSS-токены |
| `expose` | Публичные входы микрофронтенда |

Имена слоёв соответствуют `ARCHITECTURE.frontend.md`: отдельного `application` нет, `app` содержит только прикладной код. `core` и `app` не импортируют React, Pixi, DOM или WebGL. Разрешён только AbortSignal для чтений. `main` собирает зависимости, UI получает готовые операции через `ui/di`; контроллеры не создают репозитории или команды. Board остаётся отдельной верхнеуровневой папкой UI по запросу владельца.

Документ использует исключение для редакторов из раздела 6.1 архитектуры: локальная реплика владеет операциями, историей и синхронизацией. Это не второе универсальное хранилище серверных сущностей. Коллекции доступны извне только для чтения; строки поступают через проверяемые страницы, отдельный метод меняет лишь состояние загрузки. Ревизия меняется после подтверждённого сохранения. Правила редактирования вынесены в чистые процессы core.

Публичный `index.ts` принадлежит пакету внутри слоя. В корне слоёв `core`, `env`, `shared`, `app` и `main` файлов `index.ts` нет. Межпапочные импорты используют эти входы; внутренние файлы одного пакета могут обращаться друг к другу напрямую, чтобы не создавать циклы через собственный barrel. Проверка в `editor:lint` обнаруживает пропущенные входы, обход публичного API, неверные направления слоёв, зависимости бизнес-кода от браузера и циклы исполнения. Transport не знает модели приложения; кеш работает через порты и не создаёт конкретные репозитории.

Внутри board раздельно представлены модель, геометрия, камера, текст, события и рендеринг. Рендеринг разделён на карточки, строки, подписи, оформление, связи и слои сцены; lifecycle отдельно владеет графическими ресурсами. Это внутренние UI-модули, а не дополнительные бизнес-слои.

Базовые страницы неизменяемы; семантические операции и история хранятся отдельно. Подгрузка страницы не является изменением документа. Снимки и запоздалые ответы проверяются по ресурсу, ревизии и контексту. Обычное окно содержит до 100 строк, дополнительные строки закрепляются ожидающими правками, раскрытыми связями и ограниченной историей из 100 действий. Кеш хранит до 64 страниц. Наличие полученной последней страницы не означает, что все старые строки ещё находятся в памяти. Операции, которым требуется неизвестная смежность или проверка предков, требуют дополнительной загрузки.

## 3. Federation и доставка

Оба приложения остаются на Webpack 5. Используется `@module-federation/enhanced` 0.17.0: runtime-регистрация remote по manifest и генерация dts доступны без переписывания сборки хоста. PixiJS 8.11.0 принадлежит только редактору. Общие singleton-зависимости: React 19.1.0 и ReactDOM 19.1.0, requiredVersion берётся из package.json. React-router редактору не нужен.

Хост лениво загружает Editor через React.lazy/Suspense. Error boundary показывает сообщение и повтор; повтор создаёт новый lazy loader и перечитывает runtime-конфигурацию. Асинхронный bootstrap отделяет регистрацию shared-зависимостей от начала React.

Dev middleware читает `EDITOR_REMOTE_MANIFEST_URL` и `EDITOR_API_BASE_URL`. Production получает адрес из `/editor-runtime.json`, который указывает на remote `mf-manifest.json`. Адрес не вшит в host bundle. Размещение и CORS задаются при deployment. Хешированные chunks старых релизов сохраняются для активных клиентов. Пустой deployment URL в исходном runtime-файле требует настройки перед выкладкой.

Producer генерирует `@mf-types.zip`; host build потребляет этот артефакт либо URL `EDITOR_TYPES_URL`. Generated declarations не коммитятся. Совместимость runtime-контракта между независимо выкладываемыми релизами остаётся обязанностью deployment.

Для dev remote задано `manifest.disableAssetsAnalyze: true`, в production анализ включён. В установленном manifest plugin 0.17.0 после горячей пересборки список exposed assets включает `.hot-update.js`. Загрузка этого списка новой страницей хоста воспроизводит `self.webpackHotUpdateschema_editor is not a function`. Поддерживаемая этой версией опция исключает предварительный анализ assets в dev; container продолжает загружать обычные chunks, HMR остаётся включён. Фильтровать ошибку в тестах или обновлять историческую зависимость не требуется.

## 4. Доска и графика

Доска имеет императивный интерфейс `createSchemaBoard`, `setModel`, `on`, `viewport`, `arrange`, `destroy`. `ready` завершает загрузку шрифтов и инициализацию WebGL. BoardModel описывает отображение, не серверный документ. Связь адресует строку через memberId, а карточку через blockId. nodeId не подменяет экземпляр карточки.

Весь фон, карточки, текст, переключатели вариантов, состояния загрузки, плашки раскрытия и связи рисуются Pixi. Панели остаются в DOM. Единственное исключение внутри доски: временный input переименования, который учитывает камеру, IME, Enter/Escape и уничтожается при смене документа или unmount. Никаких постоянных DOM-карточек поверх canvas.

Фон создаётся в экранных координатах при старте и resize, не при движении камеры: светлая основа, три мягких пятна и детерминированное зерно. Строки и Text сохраняются между обновлениями. Наведение меняет состояние затронутой строки и соседние разделители. Связи группируются в Graphics по слоям; изменение состояния или геометрии инвалидирует соответствующий слой. Видимая рабочая область ограничивает число графических объектов.

Карточка показывает локальное окно максимум из десяти уже загруженных строк. Колесо над строками прокручивает это окно; снаружи сдвигает камеру, Ctrl+колесо масштабирует к курсору. Клавиатурная навигация и индикатор связи на границе раскрывают нужную строку по memberId. Подгрузка серверной страницы не смешивается с прокруткой локального окна. Связи используют три постоянных Graphics: обычные, незагруженные и выбранные. Неизменившийся набор видимых связей при небольшом сдвиге камеры не перерисовывается.

## 5. Текст, раскладка и детализация

Используется Pixi Text с системным стеком шрифтов, общими TextStyle и ограниченным кешем измерений по строке/стилю (2048 записей). До первой раскладки ожидается document.fonts.ready. Неизменившиеся подписи не создаются заново при наведении. Разрешение текста обновляется через 160 мс после остановки масштаба; devicePixelRatio ограничен 2. BitmapText не добавлен: доказательств необходимости смены текста пока нет.

Собственная детерминированная раскладка дерева располагает родителей слева, детей справа, сохраняя закреплённые позиции. Дополнительная библиотека раскладки не нужна. Проверяются повторяемость, отсутствие пересечений автоматически размещённых карточек, привязка соединений к строкам и сохранение явных позиций.

Камера ограничена диапазоном 0.12..3. Уровни детализации (LOD): overview ниже 0.35, working от 0.35 до 1.2 включительно, detailed выше 1.2. Числа выбраны по смыслу экранов 07, не как масштабирование его типографики. Overview скрывает текст строк и объединяет однотипные связи; working показывает строки; detailed добавляет наблюдения и пояснения. Визуальная сцена 07 показывает три независимых представления на одном фоне. Камера без анимации уважает reduced motion без дополнительного движения.

Стандартные размеры: заголовок 34 px и строка 28 px. Иллюстративные эталоны 05 и 07 содержат увеличенные карточки, поэтому модель допускает явные metrics: anatomy 44/36, comparison 40/34, detailed 44/38, с дополнительными размерами footer/warning/note. Это те же компоненты и hit geometry, не отдельная рисованная картинка. Обычные карточки используют 34/28. Связи заканчиваются на фактической границе карточки, даже если SVG-иллюстрация исходного экрана заходит внутрь на несколько пикселей.

В эталоне 05 ползунок изображён около середины, хотя подпись сообщает строки 3-7 из 412. Реальное окно удерживает 50 строк: позиция 3-7 находится близко к началу локального диапазона. Редактор показывает вычисленное положение, сохраняющее связь ползунка с колесом и клавиатурой. Копировать среднее положение из иллюстрации означало бы сообщать пользователю неверную позицию. Это осознанное отличие индикатора, не изменение размеров карточки или строк.

## 6. Производительность и проверки

Цель для среднего ноутбука: интерактивный кадр до 16.7 мс при документе 2000 карточек и 4000 связей. Сам документ, загруженные страницы и видимые графические объекты измеряются отдельно. Пауза в вводе не должна заставлять renderer постоянно перерисовывать сцену. Общая 9-slice тень создаётся один раз на экземпляр доски; text/graphics освобождаются при выходе из рабочего набора и при уничтожении.

Фактические frame median/p95, память, сценарии и профиль фиксируются в `docs/editor/PERF.md`. SwiftShader в WSL проверяет WebGL-корректность, но не доказывает 60 FPS на аппаратном GPU среднего ноутбука. Невыполненный бюджет описывается с измеренным узким местом.

Модульные тесты проверяют документ, кеш, DTO, раскладку, model diff, LOD, hit testing, разделители, масштаб к курсору и события. Browser harness проверяет реальные pointer/keyboard input, HTTP-адаптер, lifecycle mount, host federation/retry, общий React и изоляцию CSS. Visual harness сохраняет actual, сравнения с эталонами и результаты в `VISUAL_REVIEW.md`; успешный screenshot-тест сам по себе не означает визуального соответствия.

## 7. Последствия

Редактор можно разрабатывать и проверять отдельно, не раскрывая его внутренние слои хосту. Цена: отдельный runtime manifest, версия публичного контракта, совместимые React dependencies и отдельная эксплуатация remote. Минимальная оболочка не реализует весь конструктор, экспорт и семантическую замену/объединение по наблюдениям. Эти действия остаются явно недоступными до следующего продуктового этапа и API v2.
