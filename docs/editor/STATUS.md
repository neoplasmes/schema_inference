# Состояние редактора схем

Ветка: `feat/schema-editor`. Новый редактор размещён в `apps/editor`, старый upload-процесс хоста сохранён. Пуш и pull request не выполнялись.

## Реализовано

- Отдельное приложение Webpack 5/React/TypeScript strict, зарегистрированное в moon и существующем pnpm workspace. Миграция пакетного менеджера не требовалась.
- Module Federation enhanced 0.17.0 в обоих приложениях, async bootstrap, singleton React/ReactDOM, remote manifest и генерируемые типы. Хост использует только публичные Editor/mount exports.
- Явный контракт schema/analysis вместо отсутствующего projectId. HTTP-адаптер API v2, проверки идентичности ответов, отдельный fixture-адаптер, команды сохранения и запросы страниц.
- Независимые от Pixi/React документ, операции переименования/переноса, Undo/Redo, подтверждение changeset, защита локальных изменений от запоздалых страниц. Неопределённый результат записи сохраняет clientMutationId для повтора; окончательный отказ позволяет исправить данные и отправить новый changeset.
- Pixi WebGL-доска с фоном, карточками, связями от строк, состояниями наблюдений/замены/загрузки, уровнями детализации, камерой, выбором и переносами. Ввод имени использует временный DOM input.
- Минимальная DOM-оболочка с доступным деревом, выбором, инспектором и стеклянными панелями. Стили изолированы CSS Modules и корневым селектором токенов.
- Сцены эталонов 01/02/03/05/06/07/11 и нагрузочные сценарии. HTTP-запуск и Playwright Chromium в WSL используют программный WebGL.

## Модульность и история

Исходные девять коммитов разделены на 33 логических шага. Все девять контрольных деревьев и итоговое содержимое сохранены побайтно; даты окончания исходных этапов сохранены. Резервная ветка с исходной историей сохранена. Промежуточные сборки новой исторической цепочки отдельно не проверялись: исходная конфигурация сборки появляется только на шестом этапе.

Слои редактора теперь называются `core`, `app`, `env`, `ui`, `main`, `shared`. Отдельной папки `application` нет. Board остаётся в `src/board`, внутри разделены слои сцены, карточки, строки, оформление, геометрия, камера и обработчики ввода. UI разделён на страницу, модель сессии, чтения ветвей, сохранение, действия, проекцию и виджеты оболочки.

99 пакетов исходников имеют `index.ts`; внешние импорты проходят через публичные входы пакетов. В корне слоёв `core`, `env`, `shared`, `app` и `main` файлов `index.ts` нет. Lint автоматически проверяет это правило, направления зависимостей, независимость бизнес-кода от фреймворков и отсутствие циклов исполнения. Main создаёт конкретные зависимости и готовые команды/запросы, UI получает их через DI. Документ-реплика владеет страницами и историей; извне можно менять состояние загрузки, но нельзя произвольно заменить окно или ревизию.

Для рефакторинга установлены четыре выбранных skill: `improve-codebase-architecture`, `code-refactoring-refactor-clean`, `vercel-composition-patterns`, `code-review`. Они находятся в локальной `.agents/skills`, которая исключена из Git существующими пользовательскими настройками. Новые зависимости приложения не добавлялись.

Сам рефакторинг записан ещё 14 логическими коммитами: модель, прикладные операции, документ, адаптеры, части доски, UI, сборка зависимостей, проверки и документация. Пользовательские незакоммиченные изменения, существовавшие до задачи, сохранены отдельно от этих коммитов.

## Как запустить

Используются закреплённые Node 22.15.0, pnpm 10.13.1 и moon 1.35.4. После `pnpm install --frozen-lockfile`:

```sh
moon run client:dev
```

Хост: `http://localhost:3000/edit?demo=1`. Редактор: `http://localhost:3010`. Адреса должны использовать одинаковое имя хоста: сочетание `127.0.0.1` и `localhost` блокируется проверкой cross-site запросов dev server.

```sh
moon run editor:playground
moon run editor:visual
moon run editor:perf
pnpm --dir apps/editor exec tsx visual/browser.ts
moon run editor:typecheck editor:lint editor:test editor:build
moon run client:build
```

Пример сцены: `http://localhost:3010/?scene=card-anatomy`. Каноническая `stress` содержит 2000 карточек и 4000 связей; дополнительные сценарии исследуют большой документ, плотный кадр и длинную коллекцию. Visual/perf запускают локальный сервер при его отсутствии и не останавливают уже работавший сервер. Для браузерных проверок нужен Chromium из Playwright 1.54.1: `pnpm --dir apps/editor exec playwright install chromium`.

В текущем WSL глобальная конфигурация нового proto несовместима со старым закреплённым бинарником. Изоляция конфигурации без изменения пользовательских настроек:

```sh
PROTO_HOME="$PWD/.proto" /home/neoplasmes/.proto/tools/proto/0.48.1/proto run moon -- run client:dev
```

Dev-конфигурация хоста читает `EDITOR_REMOTE_MANIFEST_URL` и `EDITOR_API_BASE_URL`. Production требует настроенного `editor-runtime.json` с URL удалённого `mf-manifest.json`. `apiBaseUrl` не включает `/api/v2`: этот суффикс добавляет адаптер. Хост собирается с generated dts из editor build; альтернативный источник задаётся `EDITOR_TYPES_URL`.

## Проверки и артефакты

`moon run editor:typecheck editor:lint editor:test editor:build client:build client:typecheck` проходит: 127 модульных тестов в 21 файле, обе production-сборки успешны. Совместный `client:dev` действительно поднимает оба приложения. Проверена установка lock-файла из коммита с `--frozen-lockfile --ignore-scripts` в отдельном временном workspace.

Холодный `editor:visual` самостоятельно поднял сервер, снял семь сцен и 20 сравнений, завершил свой процесс и освободил порт 3010. Проверка освобождения выполнена повторным bind порта. При уже запущенном сервере harness использует его и оставляет работающим.

Модульные тесты проверяют модель документа, загрузку/кеш/отмену чтений, исторические операции, DTO, раскладку, model diff, hit testing, уровни детализации, разделители, камеру и события. Browser harness проверяет пользовательский ввод, API v2 через контролируемые HTTP-ответы, ресурсную изоляцию mount/update/unmount, federation/retry/общий React и CSS-изоляцию. Эти HTTP-проверки не означают, что API v2 уже реализован в `apps/server`.

Финальный браузерный прогон: 20 из 20 сценариев проходят. Хост и remote используют один объект библиотеки React; восстановление после недоступного remote проходит. Computed styles страницы хоста совпадают до, во время и после mount; снимки до и после совпадают побайтово. Семь визуальных сцен сняты без ошибок страницы, все 20 сравнений просмотрены независимым проверяющим; ведущий агент дополнительно просмотрел каждую сцену и снимок хоста. Открытых нарушений жёстких правил нет; обоснованные отличия перечислены в VISUAL_REVIEW и ADR 0002.

Итоговые результаты визуальной сверки и её допустимые отклонения находятся в [VISUAL_REVIEW.md](./VISUAL_REVIEW.md). Измеренные frame median/p95, память и ограничения программного рендеринга находятся в [PERF.md](./PERF.md). Actual/compare/trace/profile являются воспроизводимыми локальными артефактами, не исходным кодом; каталоги `apps/editor/visual/actual` и `compare` исключены из Git.

Бюджет 60 FPS в проверенной WSL/SwiftShader-среде не достигнут. Для `stress` интервалы реально отрисованных кадров составили median/p95 262,0/285,9 мс при pan и 297,2/333,3 мс при zoom через Playwright. Непрерывный синтетический ввод подтвердил задержки без отдельной команды драйвера на каждый шаг. JS heap вырос с 47,9 до 53,2 MiB без принудительной сборки мусора; в покое во всех трёх нагрузках новых draw frames нет. Профиль отделяет высокую стоимость программного graphics backend от дополнительного хвоста растеризации текста при первом zoom плотной сцены. Это документированное ограничение, а не подтверждение аппаратной производительности.

Исторические версии проверены по официальным release/package metadata: все 153 добавленных разрешённых версии существовали к исходному срезу 17 июля 2025. В lock закреплены транзитивные зависимости, автоматический moon dedupe отключён, чтобы установка не обновляла историческое разрешение. Исходный аудит находится в локальном `artifacts/editor-platform/historical-audit.json`.

## Известные границы и следующие шаги

1. В текущем сервере нет постоянных schema/analysis snapshots, страниц и changesets API v2. Нужно реализовать этот контракт и подключить настоящий upload-анализ к новому маршруту. До этого `/edit/legacy` обслуживает старый процесс; `/edit?demo=1` явно демонстрационный.
2. Полная палитра и редактор ограничений, семантические replace/allow-both/merge/custom, provenance bindings и серверный XSD export относятся к следующему этапу. Минимальная оболочка показывает их доступность честно; просмотр варианта не меняет документ.
3. Нет разрешения конфликтов серверных ревизий: конфликт сохраняет локальные правки и блокирует ошибочное повторное применение к новой базе. Для production нужен отдельный сценарий согласования.
4. Deployment должен обеспечить manifest/chunks CORS, совместимые версии публичного контракта и собственную политику авторизации API. Текущая задача не выполняет выкладку.
5. Повторить сохранённый benchmark на целевом GPU и production build. Для плотной сцены отдельно проверить отложенное повышение разрешения текста: при медленных программных кадрах пауза 160 мс истекает между шагами zoom и вызывает дополнительные обновления текстур. Конкретные профили и предложения находятся в PERF.
